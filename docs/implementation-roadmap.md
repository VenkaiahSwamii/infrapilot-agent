# InfraPilot Enterprise Implementation Roadmap

This roadmap turns the enterprise architecture into incremental engineering phases. Each phase should leave the product deployable and testable.

## Phase 1: Multi-Tenant Core

- Add `organizations`, `organization_members`, and RBAC.
- Scope every existing user, machine, metric, and alert query by `organization_id`.
- Add organization-aware JWT claims.
- Replace global dashboard endpoints with organization-scoped endpoints.
- Add frontend organization selector and organization overview cards.
- Add audit logs for organization and role changes.

Exit criteria:

- One backend can host multiple companies.
- Users only see machines, alerts, logs, and metrics from their organization.
- Existing machine registration creates records under an organization.

## Phase 2: Secure Agent Enrollment

- Add `enrollment_tokens` and `machine_api_keys`.
- Store only hashed tokens and keys.
- Implement `POST /api/v1/agent/enroll`.
- Implement `GET /api/v1/agent/config`.
- Add agent CLI:
  - `agentctl enroll --server https://... --token ...`
  - `agentctl service install`
  - `agentctl status`
- Add machine key rotation.

Exit criteria:

- Customers install the agent once.
- Machines register automatically into the correct organization.
- No SSH, RDP, or manual connection is required.

## Phase 3: Metric Pipeline

- Introduce durable ingestion queue.
- Add worker pool for metrics, inventory, logs, and alerts.
- Split `machine_latest_state` from historical `metric_samples`.
- Add batch IDs and deduplication.
- Add 1-minute rollups.
- Add API payload limits, schema validation, rate limits, and backpressure.

Exit criteria:

- Backend can absorb bursts from thousands of agents.
- Dashboard receives real-time latest state.
- Historical charts query rollups instead of raw samples where possible.

## Phase 4: Enterprise Collectors

- Add CPU, RAM, swap, load, uptime, and temperature.
- Add filesystem, disk IO, IOPS, SMART, RAID/LVM where available.
- Add network throughput, latency, packet loss, connections, and open ports.
- Add process and top process collector.
- Add Docker collector for containers, images, volumes, networks, logs.
- Add Kubernetes collector for nodes, pods, workloads, services, PV/PVC.
- Add Linux systemd/journal/kernel log collector.
- Add Windows services/event-log collector.

Exit criteria:

- Machine detail page can show identity, OS, storage, network, process, Docker, Kubernetes, and logs.

## Phase 5: Real-Time Dashboard

- Add organization-scoped WebSocket endpoint.
- Add live overview cards and status indicators.
- Add machine detail subscriptions.
- Add reconnect and REST backfill on the frontend.
- Add search and filters for organization, machine type, OS, status, tags, and severity.
- Add chart ranges for 1h, 24h, 7d, and 30d.

Exit criteria:

- Dashboard updates automatically every few seconds without refresh.
- Users can move from enterprise overview to organization and machine details.

## Phase 6: Alerting

- Add `alert_rules`, `alerts`, and `alert_events`.
- Implement threshold rules:
  - CPU > 90%
  - RAM > 90%
  - Disk/filesystem > 90%
  - Machine offline
  - Container down
  - Pod failed
  - Node not ready
  - Storage full or degraded
- Add alert acknowledgement and resolution.
- Add WebSocket alert events.
- Add mute windows and per-organization rule overrides.

Exit criteria:

- Alerts are generated by workers and delivered to dashboard in real time.
- Operators can acknowledge and resolve alerts with audit history.

## Phase 7: Production Deployment

- Dockerize API, worker, scheduler, frontend, and agent.
- Add Docker Compose for local development.
- Add Kubernetes manifests.
- Add TLS ingress.
- Add secrets management.
- Add OpenTelemetry, Prometheus, and Grafana.
- Add database backups and restore testing.
- Add CI build/test/deploy workflow.

Exit criteria:

- Platform can be deployed in staging and production with repeatable infrastructure.

## Phase 8: Scale and Reliability

- Add TimescaleDB hypertables or native PostgreSQL partitioning.
- Add retention and downsampling policies.
- Add read replicas for analytics.
- Add load tests for 1k, 10k, and 100k machines.
- Add queue dead-letter handling.
- Add WebSocket fan-out via Redis/NATS/Kafka.
- Add organization quotas and rate limits.

Exit criteria:

- The system has measured capacity targets and documented operating limits.

## Phase 9: AI Features

- Add anomaly baselines by machine and organization.
- Add forecasting jobs for disk, CPU, memory, and bandwidth.
- Add disk failure prediction using SMART and IO history.
- Add unusual traffic and CPU spike detection.
- Add AI recommendations attached to alerts.
- Add incident summary generation.

Exit criteria:

- Dashboard surfaces predictive and recommendation-based insights in addition to rule alerts.
